## What R2 changes from R1

| Item | R2 position |
|---|---|
| **A1. Precedence** | A goal succeeds only when its whole declared predicate is verified with the fort alive, including any sustained interval. G1 is a dated checkpoint plus a no-deaths history, with no extra interval. Verified loss at or before the goal-completion tick wins, judged by the event's simulation time, not when it was received. An uncertain disconnect goes to reconciliation first. If evidence can't be recovered within the declared recovery limit, the result is `infrastructure_failure` with outcome uncertainty. An unresolved condition is never labeled as a verified ending. |
| **A2. Lifecycle gate** | Ten consecutive unattended attempts must each go from world creation through the fixed-profile embark to the first fortress tick, with sensor evidence. Every failed attempt is recorded. This proves fixture reliability, not arbitrary-world reliability. Save and reload get their own gate. **An assisted embark does not satisfy full-startup success** without an explicit scope revision by the maintainer. |
| **A3. Catalogue** | The tool list is accepted as a proposed contract, with **reload and verify-loaded-session** added. Each operation documents its arguments, preconditions, effects, evidence and failure behavior. The coverage mapping must be confirmed against a pinned upstream revision. In v1, military, trade, healthcare and justice *events* are still observed, and unsupported responses are reported. |
| **A4. Budgets** | Each scenario declares limits on model calls, input tokens, output tokens, wall time and game ticks, plus recovery limits and retry accounting. Runs record cache use, cost assumptions and local compute. G1 numbers are calibrated after G0, then frozen before comparisons. |
| **Observations** | Snapshots carry save and session identity. Uncertainty and stale data are marked. Gaps in the event history are exposed, never silently skipped. |

## Validation order

1. Pin versions and audit reuse.
2. Run G0 on a prepared save: observation accuracy, ten steps, interrupts and reconnect.
3. Run blocked brewing, with retry and work-completion evidence.
4. Run two independent harnesses on the unchanged controller.
5. Pass the lifecycle gate and the save/reload gate.
6. Run full startup to G1, plus a separate loss fixture.
7. Move on to G2–G4.
